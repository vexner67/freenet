Сайт, в отличие от API, кешируется (в нём нет ничего личного): страницу и файл по простому адресу `/static/…` браузер каждый раз сверяет с сервером (`Cache-Control: no-cache`, ответ 304, у страницы — `ETag`), а по адресу со своей версией — `/static/c/<версия>/<файл>` — файл отдаётся навсегда (`immutable`). Версия у каждого файла своя (`rest/assets.go`): дайджест его содержимого и версий файлов, которые он называет, — после деплоя браузер качает только изменившееся. Называет файл другой двумя способами, и в оба gateway подставляет версию: модуль импортирует модуль рядом с собой (`from './layout.js'` → `from '/static/c/<версия>/layout.js'` — у модуля один адрес, кто бы его ни импортировал, иначе он загрузился бы дважды), а страница, скрипт и таблица стилей называют файл целым путём одной строкой (`"/static/club.svg"`, в любых кавычках). Поэтому изменившийся файл меняет версию и тех, кто его называет, по цепочке; модули, импортирующие друг друга по кругу (`posts.js` ↔ `share.js`), делят одну версию (сильно связные компоненты, `circles`). Файлы читаются в память и перечитываются, когда изменились их имена, размеры или времена (проверка — не чаще раза в секунду): сохранённый при разработке файл отдаётся сразу. Файл по адресу с чужой версией и по адресу прежних сборок `/static/v/<версия сайта>/…` (страница, открытая до деплоя) отдаётся с `no-cache`. Перед скриптом страницы (`<script type="module">`) gateway перечисляет `<link rel="modulepreload">` всех модулей, которые он импортирует на любой глубине (`preloading` в `rest/pages.go`, импорты файла — `staticFile.imports`): браузер просит их все разом, а не узнаёт о каждом от предыдущего. Поэтому путь к файлу в HTML и в скрипте — только целиком, `"/static/…"` одной строкой, без склейки и шаблонов: иначе он останется простым адресом без версии. `TestAssets_Website` проверяет это на самом сайте. Новые пути страниц добавлять в зарезервированные никнеймы (`user/internal/user/nickname.go`).
